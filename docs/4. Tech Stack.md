# Technology and development

| Layer | Implementation |
| --- | --- |
| Frontend | React 19, TypeScript 6, Vite 8; TanStack Router/Query/Table/Store/Hotkeys/Pacer, TanStack Form 2 alpha, TanStack DB (local-storage collections for per-browser preferences, saved ledger filters and transaction templates) |
| Package manager | nub 0.9.2; native nub.lock, frozen installs in CI and Docker |
| Styling | Tailwind 4, shadcn/ui (base-nova style) on Base UI, react-day-picker, Lucide icons, Recharts, self-hosted typefaces for the per-browser typeface choice: Source Serif 4, Source Sans 3, Inter, Newsreader, IBM Plex Sans, IBM Plex Serif and Atkinson Hyperlegible Next (woff2 in `src/assets/fonts`, OFL) |
| Localization | react-i18next, EN/LT JSON dictionaries and Intl formatters |
| API | .NET 10, FastEndpoints, FluentValidation, plain feature services |
| Persistence | EF Core/Npgsql, PostgreSQL 16 |
| Authentication | ASP.NET Core Identity users, FastEndpoints.Security JWTs in HttpOnly cookies, optional TOTP |
| Contract | FastEndpoints OpenAPI and Orval-generated query hooks/models |
| Telemetry | Serilog console logs; optional OpenTelemetry traces, metrics and logs exported over OTLP to the standalone .NET Aspire dashboard |
| PDF | PDFsharp-MigraDoc (MIT). Fonts come from the host through `PdfFontResolver`: DejaVu Sans on Linux (the API image installs `fonts-dejavu-core`), Arial on Windows and macOS |
| Checks | xUnit v3 with FastEndpoints.Testing, real PostgreSQL integration tests (Testcontainers), NetArchTest, Oxc, TypeScript/Vite, Vitest unit and DOM tests, Storybook stories run in jsdom by Vitest with an axe-core scan (Storybook itself is for manual review, colour contrast included), Playwright end-to-end smoke tests, lefthook git hooks, `just` recipes |
| Deployment | Docker Compose; Caddy serves the SPA and proxies /api; named volumes `db_data` (PostgreSQL), `auth_keys` (signing and Data Protection keys), `backups` (backup archives) and `attachments` (files attached to transactions), each mounted only where it is needed |

Exact dependency versions are in the project/package manifests and lockfile. The backend uses one application project with Domain, Infrastructure, Endpoints and Common folders, plus a test project. The earlier separate Domain/Infrastructure-project design was not retained.

`nub run --cwd frontend build` includes TypeScript checking. `nub run --cwd frontend lint` and `format:check` are separate checks. Backend integration tests normally create a disposable PostgreSQL container. The optional `JX_TEST_POSTGRES` connection string supports an already-running disposable PostgreSQL database whose name begins `jx_test_`; never point it at an application database.

Frontend lint rules live in `frontend/.oxlintrc.json`. The `correctness`, `suspicious` and `perf` categories are errors, with the `react`, `typescript`, `import`, `jsx-a11y`, `unicorn`, `oxc` and `promise` plugins enabled. Type-aware linting is on (`options.typeAware`, backed by the `oxlint-tsgolint` package), so `typescript/no-deprecated` fails the lint on any use of an API or type marked `@deprecated`, in our code or in a dependency; the fix is the replacement named in the deprecation note (for TanStack Query that means `queryClient.query(...)` instead of `fetchQuery`, `prefetchQuery` and `ensureQueryData`). The other type-aware rules are errors too, among them `no-floating-promises` (await the promise, or mark a deliberate fire-and-forget with `void`) and `no-unsafe-type-assertion` (narrow with a type guard, parse untrusted JSON with a zod schema, or type the value at its source instead of casting). Lint findings are fixed in the code; suppression comments are not used. Style conventions are enforced as errors: function declarations over arrow-function constants, `interface` for object types, type-only imports, named exports (default exports are allowed only for stories, routes, Storybook and tool configuration), braces on every block, kebab-case filenames and no import cycles. `no-restricted-imports` bans `useEffect`, `useLayoutEffect`, `useMemo` and `useCallback` from `react`, named or through a namespace import, because the React Compiler memoizes and effects are replaced by render-time derivation, event handlers, TanStack Query, Hotkeys and Pacer; the vendored primitives under `src/components/ui` are exempt only because they use `import * as React` for types. `typescript/no-non-null-assertion` is a warning in application code until the existing assertions are removed. Vendored primitives under `src/components/ui` are exempt from `no-shadow`, `no-restricted-imports`, `react/no-unstable-nested-components` and `jsx-a11y/label-has-associated-control`. `unicorn/no-useless-undefined` stays disabled because its autofix removes arguments that Zod `.catch(undefined)` and `useRef(undefined)` require.

Design-system rules come from the `@shadcn/lint` Oxlint JS plugin, registered under `jsPlugins` in the same config; all six of its rules are errors. `no-restyle` allows layout classes (margin, width, alignment, transforms) plus the `stale` utility on every design-system component, and contracts widen that where the page owns part of the styling: containers (`Card`, `Section`, `StaleRegion`, `SplitColumns`, `ScrollRegion` and any `*Content`, `*Header`, `*Footer`, `*Group`, `*Panel`) accept spacing; `TableCell` and `TableHead` accept spacing, typography and the muted, income and expense text colours; `*Title` accepts typography; `Skeleton` accepts `rounded-*`; `Input` accepts a font family; `TableRow` accepts the muted text colour for de-emphasised rows. `no-arbitrary-values` allows arbitrary layout values, so grid templates and viewport-relative widths stay inline while type sizes, line heights and letter spacing must come from the theme. `no-unknown-classes` allows sonner's `toaster` marker class. Inside `src/components/ui` the `no-restyle`, `no-arbitrary-values` and `require-static-classes` rules are off, because the primitives style themselves and call their own variant functions; `no-raw-colors` and `no-inline-styles` still apply there. Fix findings with a variant, a contract or a theme token rather than a suppression comment. A component that must take a caller's styling choice does so through a prop with a fixed set of values (`EmptyText size`, `SelectTrigger size="icon"`, `TextField monospace`), never a class-name prop, so the linter can read what is applied. Dynamic values reach CSS through custom properties (`style={{ "--meter-fill": … }}` with `w-(--meter-fill)`), typed by the `CSSProperties` augmentation in `frontend/src/react.d.ts`.

Frontend formatting rules live in `frontend/.oxfmtrc.json`. Besides layout (100-column width, LF line endings, final newline), the formatter sorts imports into side-effect, Node built-in, external package, `@/` internal and relative groups without blank lines between them, sorts Tailwind classes in `class`, `className`, `cn`, `cva` and `clsx` using `src/global.css` as the Tailwind v4 stylesheet, and sorts `package.json` keys while leaving script order alone. Generated API code, the generated route tree, the MSW worker and build output are ignored. `frontend/.gitattributes` keeps frontend files LF in the repository and the working tree so the formatter and Git agree on Windows.
