# 4. Tech Stack

A self-hosted, locally-deployed app. React + **TanStack** on the front-end, **ASP.NET Core** on the back-end, all runnable from your own machine. The frontend leans on the TanStack ecosystem (Router, Query, Table, Form) throughout ([[9. Open questions & decisions|D20]]). See [[7. Architecture notes]] for how these fit together and [[10. Resources & links]] for docs.

## Front-end
| Concern | Choice | Notes |
|---------|--------|-------|
| Build tool | Vite | Fast dev server and builds; the base for the whole frontend |
| Framework | React | UI library, built and bundled with Vite |
| Language | TypeScript | Type safety across the frontend |
| Routing | TanStack Router | Type-safe, file-based route tree with first-class data loading |
| Data fetching | TanStack Query | Server-state caching; keeps balances and lists in sync after edits |
| API client | Generated from OpenAPI (Orval) | Typed fetchers + TanStack Query hooks, regenerated when the API changes ([[7. Architecture notes#API contract & client generation]]) |
| Tables | TanStack Table | Transaction lists with sorting, filtering, and pagination |
| Forms & validation | TanStack Form + zod | Form state + end-to-end validation; schemas mirror the API ([[7. Architecture notes#Frontend conventions]]) |
| Styling | Tailwind CSS | Utility-first styling (dark mode is a later enhancement) |
| UI components | shadcn/ui (Radix + Tailwind) | Accessible primitives copied into `components/ui/` |
| Charts | Recharts | Dashboard and spending-breakdown charts |
| Localization | react-i18next | English + Lithuanian UI strings in `locales/` files ([[8. Non-functional requirements#Localization (i18n)]]) |
| Client state | TanStack Store | Small client-only state; server state stays in TanStack Query |

## Back-end
| Concern     | Choice                | Notes                                                |
| ----------- | --------------------- | ---------------------------------------------------- |
| Runtime     | .NET 10               | Long-term support release                            |
| Language    | C#                    | Backend language                                     |
| API framework | ASP.NET Core + FastEndpoints | REPR (Request/Endpoint/Response) instead of MVC controllers ([[6. API surface]]) |
| App logic   | Plain application services | Feature services injected into endpoints + jobs; no mediator. Cross-cutting via decorators / FastEndpoints processors ([[7. Architecture notes#Application services, briefly]]) |
| ORM         | Entity Framework Core | Database access and migrations (applied on API startup) |
| Validation  | FluentValidation      | Wired through FastEndpoints; surfaces as `400` ProblemDetails |
| Auth        | ASP.NET Core Identity | User accounts, passwords, roles, **optional 2FA (TOTP)** ([[9. Open questions & decisions\|D52]]), and **remember-me** cookies |
| Email       | MailKit over SMTP     | Verification, password reset, and notification emails — **deferred to M5** ([[9. Open questions & decisions\|D53]]); SMTP config in `.env` |
| OpenAPI     | NSwag (`FastEndpoints.Swagger`) | FastEndpoints' first-class spec generation — the source of truth for the client ([[7. Architecture notes#API contract & client generation]]) |
| API docs UI | Scalar (`Scalar.AspNetCore`) | Interactive docs from the OpenAPI spec; modern replacement for Swagger UI |
| Logging     | Serilog               | Structured logs for errors and slow requests         |
| Errors      | RFC 7807 ProblemDetails + Result pattern | One global error shape; expected failures returned as `Result<T>` ([[7. Architecture notes#Global error handling]]) |
| Health checks | ASP.NET Core HealthChecks | DB ping, wired to the Docker healthcheck |
| Rate limiting | Built-in rate limiter | Throttles `/auth/*` against brute force |

## Data
| Concern      | Choice                            | Notes                                                                  |
| ------------ | --------------------------------- | ---------------------------------------------------------------------- |
| Database     | PostgreSQL                        | Runs in a single Docker container                                      |
| Money values | decimal (C#) / NUMERIC (Postgres) | Store money as decimal, never floating point, to avoid rounding errors |
| Backups      | Scheduled pg_dump to a file       | Automated database dump for safety ([[8. Non-functional requirements#Reliability & backups]]) |

## Local deployment
| Concern | Choice | Notes |
|---------|--------|-------|
| Containerization | Docker + Docker Compose | One command runs frontend, backend, and database |
| Reverse proxy | Caddy (optional) | Serves the app and handles HTTPS on your network |
| Phone access | Local IP on the same Wi-Fi, or WireGuard | Reach the app from your phone over a private VPN tunnel |
| Environment config | .env file | Connection strings and secrets, kept out of source control |

## Tooling
| Concern                  | Choice                 | Notes                             |
| ------------------------ | ---------------------- | --------------------------------- |
| Frontend package manager | pnpm                   | Fast, disk-efficient installs     |
| Backend tooling          | .NET CLI               | Build, run, and manage migrations |
| Linting / formatting     | Oxc (Oxlint + formatter) | Fast Rust-based tooling; consistent code style |
| API client codegen       | Orval (← NSwag OpenAPI) | `openapi.json` → typed TanStack Query hooks |
| Backend tests            | xUnit + Testcontainers + NetArchTest | Integration (real Postgres), unit, and architecture tests ([[7. Architecture notes#Testing]]) |
| Task runner              | just / Task            | Orchestrate dev, codegen, tests, compose ([[7. Architecture notes#Developer experience & CI]]) |
| CI                       | GitHub Actions         | Build / test / lint + OpenAPI client-drift check |
| Version control          | Git                    | Source control and history        |
