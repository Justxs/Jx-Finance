# 6. API surface

A REST API built with **FastEndpoints** (ASP.NET Core), serving the React front-end. Endpoints map to the [[5. Data model|data model]] and the [[2. Features|features]]. This table is a planning sketch; the implementation's **OpenAPI document is the source of truth**, and the typed client is generated from it ([[7. Architecture notes#API contract & client generation]]).

## Conventions
- Base path: `/api`
- **JSON shape:** property names are **camelCase** (`accountId`, `categoryId`). **Enums** serialize as **camelCase strings**, never integers — e.g. `"income"`/`"expense"`, `"checking"`, `"manual"`/`"imported"`, `"billDue"` (configured via `JsonStringEnumConverter` with a camelCase policy). The entity tables in [[5. Data model]] list the C# enum *names* (PascalCase); this is their wire form.
- **Dates & times:** timestamps are UTC **ISO-8601** (`2026-05-02T18:24:11Z`); a transaction `Date` is a plain calendar date `YYYY-MM-DD` ([[9. Open questions & decisions|D42]]). Period boundaries (e.g. "this month") use the configured `App__TimeZone` ([[9. Open questions & decisions|D56]]).
- **Money** is sent and received as a string to preserve `decimal` precision (e.g. `"12.34"`) — never a float.
- **Auth:** cookie-based session via [[4. Tech Stack#Back-end|ASP.NET Core Identity]]. Every route below requires an authenticated user and returns **only that user's own rows** (the central `UserId` filter, [[5. Data model#Ownership|ownership]], [[9. Open questions & decisions|D50]]). See [[8. Non-functional requirements#Security]]. *(Household/scope sharing — and the `scope`/`householdId` filters that came with it — are deferred to [[11. Milestones & tasks#M6 — Households & sharing|M6]], D50.)*
- Standard status codes: `200` OK, `201` Created, `204` No Content, `400` validation error, `401` unauthenticated, `403` forbidden, `404` not found.
- Validation via FluentValidation (through FastEndpoints); errors return as **RFC 7807 ProblemDetails** ([[7. Architecture notes#Global error handling]]).
- **Pagination:** every list endpoint that can grow (transactions, transfers, notifications, imports) takes `page` + `pageSize` (and `sort`) and returns a paged envelope `{ items, page, pageSize, total }`. Small reference lists (accounts, categories) may return all ([[9. Open questions & decisions|D37]]).
- **Authorization:** admin-only routes require the `Admin` role ([[9. Open questions & decisions|D35]]).

## Authorization matrix
One role axis in the MVP ([[5. Data model#User]]): the **app role** (`Admin`/`Member`) gates *user* management. Data access is **per-user** — you reach a row only if you own it ([[9. Open questions & decisions|D50]]). `setup` is the one unauthenticated route, and only when no users exist. *(A household **Owner**/**Member** role and shared-record access arrive with sharing — deferred, [[9. Open questions & decisions|D50]].)*

| Capability | Anonymous | App Member | App Admin |
|------------|:---------:|:----------:|:---------:|
| First-run `POST /api/setup` (no users yet) | ✅ | — | — |
| Sign in / out, 2FA enrol (optional) | ✅ | ✅ | ✅ |
| Own profile (`/users/me`) | — | ✅ | ✅ |
| Own accounts / transactions / transfers / etc. | — | ✅ (own) | ✅ (own) |
| **Manage app users** (`GET/POST /users`, change role, deactivate) | — | — | ✅ |

## Auth (MVP)
| Method | Path | Purpose |
|--------|------|---------|
| POST | `/api/auth/login` | Start a session (email + password; `rememberMe`; `twoFactorCode` if the user enabled 2FA) |
| POST | `/api/auth/logout` | End the session |
| POST | `/api/auth/2fa/setup` | Begin authenticator enrolment (shared key / QR) — **optional** |
| POST | `/api/auth/2fa/enable` | Verify a code and enable 2FA → recovery codes |
| POST | `/api/auth/2fa/disable` | Disable 2FA |
| POST | `/api/setup` | One-time: create the first **admin** (password set directly) when no users exist (otherwise 409) ([[9. Open questions & decisions\|D44]], [[9. Open questions & decisions\|D53]]) |
| GET  | `/api/auth/me` | Current user profile |

*Account creation is admin-only — there's no public `register` (see Users). **2FA is optional** ([[9. Open questions & decisions|D52]]): a user may enrol an authenticator; if they have, `login` needs `twoFactorCode`. Behind WireGuard you can leave it off.*

> [!note] **Deferred — email flows (M5, [[9. Open questions & decisions|D53]]).** `POST /api/auth/forgot-password`, `/api/auth/reset-password`, `/api/auth/verify-email`, and `/api/auth/resend-verification` land when SMTP is wired up ([[11. Milestones & tasks#M5 — Recurring bills & notifications]]). Until then the admin sets and resets passwords directly.

## Households (M6)
> [!note] **Built in [[11. Milestones & tasks#M6 — Households & sharing|M6]] ([[9. Open questions & decisions|D61]]).** Groups for sharing Accounts + Categories; a user can belong to many. Membership management requires the household **Owner** role (a per-household role, independent of the app-wide Admin/Member role). No standalone "list members" endpoint — `GET /api/households/{id}` already returns them.

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/api/households` | List households you belong to |
| POST | `/api/households` | Create a household (you become its Owner) |
| GET | `/api/households/{id}` | Get one (members included) |
| PUT | `/api/households/{id}` | Rename — **owner** |
| DELETE | `/api/households/{id}` | Delete — **owner**. Any shared Accounts/Categories in it revert to Personal scope first |
| POST | `/api/households/{id}/members` | Add an existing user by email — **owner** |
| PUT | `/api/households/{id}/members/{userId}` | Change a member's household role — **owner**; blocked if it would leave the household with no Owner |
| DELETE | `/api/households/{id}/members/{userId}` | Remove a member — **owner**; blocked if it would leave the household with no Owner |

|--------|------|---------|
| GET | `/api/transactions` | List / search transactions |

| PUT | `/api/transactions/{id}` | Update |

| GET | `/api/transactions/export` | CSV export — same filters as the list, no paging (*M7*) |

**`GET /api/transactions` query params** (powers search & filter, *v1.1*):
`accountId`, `categoryId`, `type` (`income`/`expense`), `from`, `to` (date range), `minAmount`, `maxAmount`, `q` (description search), `page`, `pageSize`, `sort`.

**Splitting (*v1.1*):** create/update accept an optional `lines[]` — each `{ categoryId?, amount, description? }`. When present the transaction is split (`isSplit = true`) and the lines must sum to `amount`; `GET` returns them. Spending-by-category attributes split transactions by line. See [[5. Data model#TransactionLine]].

## Reports (M7)
| Method | Path | Purpose |
|--------|------|---------|
| GET | `/api/reports/summary` | Income/expense/net + expense-by-category + a trend series for an arbitrary `dateFrom`/`dateTo` range (defaults to the current month if omitted) |

Trend bucketing is automatic: daily points for ranges up to 62 days, monthly points beyond that (`trendBucket` in the response tells the frontend which). The **Reports** page reuses this one endpoint for both custom-range reports and the yearly review (a full-year range plus a net-worth-change card computed client-side from `/api/networth/history`) — no separate "yearly review" endpoint exists.

## Import (v1.2)
| Method | Path | Purpose |
|--------|------|---------|
| POST | `/api/import/swedbank/preview` | Upload CSV → parsed rows, each flagged if it looks like a duplicate so the user can keep / edit / skip ([[9. Open questions & decisions\|D9]]) |
| POST | `/api/import/swedbank/confirm` | Commit the selected rows to an account |

**Parsing** ([[10. Resources & links#Swedbank CSV export format|format]], [[9. Open questions & decisions|D47]]): import only **row-type `20`** (skip opening-balance `10`, turnover `82`, closing-balance `86`); `D/K` → expense/income; `Suma` is positive and already in EUR. Dedup on **`Įrašo Nr.`** (stored as `Transaction.ImportRef`) so re-imports are idempotent. Rows that look like own-account transfers / cash are flagged for the user to reclassify as a [[5. Data model#Transfer (v1.1)|Transfer]].

See [[3. User flows#Flow: Import a Swedbank CSV]].

## Example payloads
Concrete shapes the generated client (and you) can rely on. Money is always a **string**; timestamps are **UTC ISO-8601**; a transaction `Date` is a plain calendar date.

**Create a transaction** — `POST /api/transactions`
```json
{
  "accountId": "8f3e…",
  "categoryId": "1a2b…",
  "type": "expense",
  "amount": "15.77",
  "date": "2026-05-02",
  "description": "Lidl"
}
```
→ `201 Created`
```json
{
  "id": "c91d…",
  "accountId": "8f3e…",
  "categoryId": "1a2b…",
  "type": "expense",
  "amount": "15.77",
  "date": "2026-05-02",
  "description": "Lidl",
  "source": "manual",
  "isSplit": false,
  "createdAt": "2026-05-02T18:24:11Z"
}
```

**Split transaction** — `POST /api/transactions` with `lines[]` (lines must sum to `amount`)
```json
{
  "accountId": "8f3e…",
  "type": "expense",
  "amount": "54.00",
  "date": "2026-05-02",
  "description": "Lidl big shop",
  "lines": [
    { "categoryId": "food…",     "amount": "40.00", "description": "Food" },
    { "categoryId": "clothes…",  "amount": "9.00",  "description": "Clothes" },
    { "categoryId": "cleaning…", "amount": "5.00",  "description": "Cleaning supplies" }
  ]
}
```
When `lines` is present `categoryId` is omitted at the top level and `isSplit` comes back `true`.

**Create an account** — `POST /api/accounts`
```json
{
  "name": "Swedbank checking",
  "type": "checking",
  "startingBalance": "1200.00",
  "scope": "shared",
  "householdId": "a1b2…"
}
```
`scope` defaults to `"personal"` if omitted, in which case `householdId` must be `null`. Setting `scope: "shared"` requires `householdId` to name a household you belong to ([[9. Open questions & decisions|D61]]); the same two fields exist on `POST/PUT /api/categories`. `Transaction`/`Transfer` responses have no `scope`/`householdId` of their own — they're visible through their `Account`'s scope.

**Paged list** — `GET /api/transactions?page=1&pageSize=20&sort=-date`
```json
{
  "items": [ { "id": "c91d…", "amount": "15.77", "date": "2026-05-02" } ],
  "page": 1,
  "pageSize": 20,
  "total": 137
}
```

**Validation error** — RFC 7807 ProblemDetails (`400`), the one error shape across the API ([[7. Architecture notes#Global error handling]])
```json
{
  "type": "https://httpstatuses.io/400",
  "title": "Validation failed",
  "status": 400,
  "errors": {
    "amount": [ "Amount must be greater than 0." ],
    "lines":  [ "Lines must sum to the transaction amount." ]
  }
}
```
