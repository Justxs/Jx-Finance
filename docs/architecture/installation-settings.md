# Installation settings

`IInstanceSettingsStore` is a singleton holding an immutable `InstanceSettingsSnapshot`. It loads the row lazily on first use, falls back to configuration defaults without caching if the database is unreachable (which also covers OpenAPI export), and is replaced after a successful save by `StoredSettings.UpdateAsync` (`Endpoints/Settings/Services`), which loads or creates the row in a transaction, applies the change, commits and only then swaps the snapshot. Each settings area has its own service and interface on top of it: `SettingsService` for the installation settings and the reporting-currency revaluation, `SmtpSettingsService`, `MarketPriceSettingsService` and `DiscordSettingsService` for their sections and tests, `ExchangeRateSyncService` for the manual rate sync, and `ExchangeRateEntryService` for the rates entered by hand. `SystemClock`, `ExchangeRateService`, `CurrencyService`, the services that pass the reporting currency to their static mappers (accounts, budgets, goals, assets and debts) and the background jobs read the snapshot, so a change takes effect on the next request with no restart. The store assumes one API process; a second instance would keep its own snapshot until restarted.

A feature switch is declared on the endpoint group: a gated group passes its `Feature` to `ApiGroup` (`ApiGroup(ApiTags.Budgets, Feature.Budgets)`), and `ApiGroup` adds a `RequiresFeature` metadata entry to every endpoint of the group through `Options`. `FeatureGateMiddleware` runs after routing and authorization, reads `context.GetEndpoint()?.Metadata.GetMetadata<RequiresFeature>()` and keeps no list of its own, so a new endpoint is gated by joining its group and a new gated feature is one argument. A disabled feature answers 404 with code `feature.disabled`, written through `ProblemResponses.WriteAsync` in the same shape an endpoint's `Send.ProblemAsync` produces. A request that matches no endpoint carries no metadata and gets the router's plain 404 or 405.
`FeatureGateTests` maps the real endpoints and checks that every route under `/api/budgets`, `/api/goals`, `/api/recurring-bills`, `/api/networth`, `/api/assets`, `/api/debts`, `/api/reports`, `/api/import`, `/api/households`, `/api/conversions`, `/api/investments`, `/api/categorization-rules`, `/api/month-close` and `/api/receipts` carries exactly the feature of its prefix and that nothing else carries one. Since 2026-09-26 the list also holds `/api/transactions/{id}/unusual` for `UnusualAmounts`, and the longest matching prefix decides. Since 2026-10-03 it holds `/api/attachments` and `/api/transactions/{transactionId}/attachments` for `Attachments`, `/api/payees` for `PayeeNames`, `/api/contacts` for `People` and `/api/accounts/forecast` for `CashFlowForecast`. Those two routes, the "not unusual" mark and its undo, are the only ones gated on the endpoint rather than the group: they live in the ungated `TransactionsGroup` and add the `RequiresFeature` entry through their own `Options`, because the rest of the ledger must answer whatever the switch says.
The one exception is `GET /api/households`, marked with `EmptyWhenFeatureOff` metadata, which answers an empty list, because account and category forms read it to offer sharing and should degrade to "nothing to share with" instead of failing. Assets and debts belong to the net worth feature; conversions belong to multi-currency.

`ActiveHouseholdMiddleware` runs straight after it and is the only thing that trusts the `X-Active-Household` header. It does nothing unless the caller is authenticated, the Households feature is on, the value parses as an id and one membership row matches it and the caller; only then does it put the id in `HttpContext.Items`, where `HttpCurrentUser.ActiveHouseholdId` finds it. `ICurrentUser` declares that property with a default implementation returning null, so the background jobs, the snapshotter and every other non-request implementation are unscoped without knowing the feature exists. The membership check itself runs before anything is stored, so it is answered by the unscoped context and cannot be narrowed by the value it is checking. `AppDbContext` reads the property inside the shareable query filter, which makes the scope a property of the data access rather than of an endpoint.

Currency restrictions are enforced where money is written: `IExchangeRateService.UnusableReason` rejects a currency that is not enabled, or any foreign currency when multi-currency is off. Updating a transaction, an investment entry or an account that already uses a now-disabled currency is allowed as long as the currency does not change. Bank statement import follows the same rule: confirming a row in a currency that is not usable answers `currency.disabled` and writes nothing of the request.

A new installation starts from `FeatureFlags.Default`, which is `FeatureFlags.All`, every switch on, except `ApiTokens`, `Locations` and `LearnedCategories`, which start off. `FeatureFlags.IsEnabled` reads each stored flag as it is, except `Feature.People`, which is on only while `Households` is on too; the client reads the same pair. `SettingsResponse` also answers `receiptReadingReady`, which `SettingsService` computes from the `ReceiptReading` switch and `IReceiptReader.IsAvailable`, whether the `tesseract` executable is on the API's `PATH`; it is not stored.

On the client, `useSettings` reads `GET /api/settings` without suspense and falls back to everything enabled (`receiptReadingReady` false, so no receipt is read before the settings arrive; `apiTokens` true like the other switches, which only shows the token section a moment early, since the server enforces the switch); `requireFeature` in a route's `beforeLoad` redirects to the dashboard using the same cached query. `GET /api/settings/public` is anonymous and carries only the installation name and default language, for the sign-in page, the brand lockup and the document title, and the two delivery flags `emailEnabled` and `discordEnabled`, which the profile's Notifications table reads to show only the channels that are set up. `supportLinkEnabled` lets the signed-out [landing page](../features/landing-page.md) offer the Ko-fi link only where an administrator shows it. `discordEnabled` is true only while the switch is on and a webhook is saved. `CurrencySelect` offers only usable currencies plus the record's current one, and its compact form renders nothing when a single currency is usable, which is how multi-currency "off" hides the pickers without each form knowing about it.
