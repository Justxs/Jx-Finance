# Accessibility and keyboard shortcuts

## Accessibility conventions
Row actions name their row: `aria-label` and `title` read "Edit: Maistas", not "Edit", so a screen reader list of buttons is usable. `ConfirmDeleteDialog` takes `itemLabel` and shows what is about to be deleted above the warning; `useConfirmedDelete` looks the label up from the list the call site already has. `FieldError` takes an `id`, and each control points at it with `aria-describedby` while the field has an error. A `SelectField` without a visible `Label` must be given `aria-label`.

Money direction never depends on color. `SummaryStats` items take `sign` (`"+"`, `"−"` or `"auto"`), and tables prefix signed amounts the same way. Charts are wrapped in an element with `role="img"` and a label, format their axis with `useAxisMoney` (compact euro amounts in the active locale) and do not animate, because Recharts animation ignores `prefers-reduced-motion`. The reports page's money flow Sankey follows the same rule: its image label states the money in, the amount spent across how many categories and the amount saved, and the category lists above it are its text equivalent, so its clickable nodes stay out of the tab order. The map of spending by place is the one exception to the no-focus rule: MapLibre's canvas takes focus for panning and zooming with the keyboard, while its wrapper is an image labelled with the three places with the most spending and the list beside the switch is its text equivalent.

With Hide amounts on, an amount is plain text such as `−€•••••`, and a screen reader reads the bullets as they are; there is no `aria-label` and no visually hidden figure, because the mode hides the number from everyone reading the screen, and an `aria-label` on a generic `<span>` fails axe's `aria-prohibited-attr`. The currency and the sign are still read, so direction is not lost. See [Interface](../features/interface.md#hide-amounts).

Controls are 36px for the desktop bookkeeping session and grow to 44px on touch devices through `pointer-coarse:` variants on `Button` and the column filter trigger. Under reduced motion view transitions keep a 100 ms cross-fade and drop all movement, so state changes stay visible without sliding.

Recharts is about 330 KB minified (97 KB gzipped) and only six components draw with it, so none of them is imported statically by a page. `lazyChart` in `src/components/chart/lazy-chart.tsx` wraps a dynamic import in `React.lazy` and its own `Suspense` with a skeleton of the chart's height, and the `index.ts` of each chart folder (`IncomeExpenseChart`, `SpendingPaceChart`, `NetWorthHistoryChart`, `NetWorthCompositionChart`, the cash-flow `ForecastChart`, the reports' `MoneyFlowChart`) exports the wrapped component. A page's text, tables and totals therefore paint from the route chunk alone and the chart chunk arrives beside them, without the layout moving when it does. `axisProps` (tick style, no axis or tick lines), `chartCursor` and the series colours (`CHART_COLOR_PRIMARY`, `CHART_COLOR_POSITIVE`, `CHART_COLOR_NEGATIVE`, and `CHART_COLOR_MUTED` for a comparison line) live in `chart-theme.ts` so that importing them does not pull Recharts in. Both net worth charts are `TimeSeriesLineChart` (`components/chart/time-series-line-chart.tsx`), which is imported by path from the lazily loaded chart files and is not re-exported from the folder's `index.ts`, because that would put Recharts in every chunk that imports the chart helpers. Stories and tests import the chart file itself and stay synchronous.

The CSV export is a plain link, but the PDF export is fetched: `ExportMenu` runs a mutation over `fetchFile` from `src/api/client.ts` (same cookies, session renewal and `ApiError` mapping as `customFetch`, but the body is read as a blob and the name comes from `Content-Disposition`) and hands the blob to `saveFile`. A link cannot show why the server refused, and the PDF endpoint answers 400 `export.tooManyRows` above 5000 rows; as a mutation that failure reaches the usual error toast. A link carries no request header either, so both URLs go through `useExportUrl` (`src/hooks/use-export-url.ts`), which takes the URL from the generated `getExport…Url` builder and adds the active household to its query string the way `customFetch` adds it to the header; the hook reads the preference, so a link follows the switcher without a refetch.

A holding's price is changed through `PUT /api/investments/securities/{id}/price` (`useSetSecurityPrice`), which a holder of the security may call; the full security form uses `PUT /api/investments/securities/{id}`, which is administrator-only, so `SecuritiesDialog` shows the edit button only when `me.role` is `Admin`. Both forms and the create form show server failures in their own `FormError` (`security.notHeld`, `conflict.duplicate` for an existing symbol and currency) instead of a toast.

`QueryBoundary` takes `errorSubject` to name what failed in the default `ErrorState`, and `error` for places where the default sentence does not fit (`null` renders nothing); whatever it renders sits in a `RetryContext` and a `CaughtErrorContext`, so an `ErrorState` or `RouteError` inside it retries the boundary without being handed a callback, and `RouteError` shows the caught error under "Technical details" (the router passes its error as a prop instead); the notification bell uses it to stay an icon (`NotificationBellUnavailable`) instead of breaking the sidebar foot. `NotificationBellSlot` is that bell inside its boundary, shared by the sidebar foot and the mobile header beside `AccountMenu`, and `useVisibleNav(role, enabled?)` gives both navigations the same feature- and role-filtered pages. `Pagination` renders nothing when there is a single page. Dialog overlays are a flat scrim without blur, in line with the paper surfaces.

Category rows on the dashboard and in reports link to the transactions list filtered by that category and date range, so a total can always be traced to its rows.

## Keyboard shortcuts
`lib/shortcuts.ts` owns the key map and is the single source for both the handler and the help dialog, so the two cannot drift. Key matching is done by TanStack Hotkeys (`@tanstack/react-hotkeys`), the project's standard for keyboard shortcuts: single keys are registered with `getHotkeyManager()` and the `g` sequences with `getSequenceManager()`. `app.tsx` calls `registerShortcuts` once at module scope, the same way it registers the session-expired listener, because the project does not use effects; that is why the managers are used directly instead of the `useHotkey` hooks. The library matches modifiers exactly and skips inputs, selects and editable elements. Registrations turn off the library's `preventDefault` and `stopPropagation` so the handler can first apply the app's own guards and only then prevent the default. The handler ignores repeated keydowns, events already handled, events from elements with a combobox or textbox role, events while a dialog is open, and everything on the sign-in and setup routes.

`n` opens the add-transaction dialog by navigating to `/transactions?new=true`; the route owns the `new` search param, so the dialog state is a URL like every other view state. `/` clicks the element marked `data-shortcut="search"` when the page has one and otherwise goes to the transactions list. `g` followed by a letter within 1.2 seconds navigates (`d` dashboard, `t` transactions, `i` import, `a` accounts, `c` categories, `b` budgets, `o` goals, `l` bills, `w` net worth, `r` reports, `h` households). `p` hides or shows amounts through `toggleAmountsHidden` in `src/stores/privacy-store.ts`, under the same guards as `n`. `?` toggles the help dialog, which the account menu also opens; its open state lives in a small TanStack Store so the key handler, the menu and the dialog share it without an effect; `openStore()` in `src/stores/open-store.ts` builds that store with its setter, toggle, reader and hook, and the command palette uses a second one. `toHotkeySteps` maps each entry of the key map to library hotkeys (`?` becomes `{ key: "?", shift: true }` because the typed hotkey strings exclude shifted punctuation); `shortcuts.dom.test.ts` covers that mapping, the ignore rules, the sequence timeout and the registered handlers against a real DOM.
