Exact dependency versions are in the project/package manifests and lockfile. The backend uses one application project with Domain, Infrastructure, Endpoints and Common folders, plus a test project. The earlier separate Domain/Infrastructure-project design was not retained.

`nub run --cwd frontend build` includes TypeScript checking. `nub run --cwd frontend lint` and `format:check` are separate checks. Backend integration tests normally create one disposable PostgreSQL container with a database per test collection. The optional `JX_TEST_POSTGRES` connection string supports an already-running disposable PostgreSQL database whose name begins `jx_test_`, beside which the tests create and drop their own databases; never point it at an application database.

Frontend lint rules live in `frontend/.oxlintrc.json`. The `correctness`, `suspicious` and `perf` categories are errors, with the `react`, `typescript`, `import`, `jsx-a11y`, `unicorn`, `oxc` and `promise` plugins enabled. Type-aware linting is on (`options.typeAware`, backed by the `oxlint-tsgolint` package), so `typescript/no-deprecated` fails the lint on any use of an API or type marked `@deprecated`, in our code or in a dependency; the fix is the replacement named in the deprecation note (for TanStack Query that means `queryClient.query(...)` instead of `fetchQuery`, `prefetchQuery` and `ensureQueryData`). The other type-aware rules are errors too, among them `no-floating-promises` (await the promise, or mark a deliberate fire-and-forget with `void`) and `no-unsafe-type-assertion` (narrow with a type guard, parse untrusted JSON with a zod schema, or type the value at its source instead of casting). Lint findings are fixed in the code; suppression comments are not used.

The config lists a rule only when no enabled category switches it on, when it needs options, or to turn a category rule off; `oxlint --rules -f json` shows each rule's category, and `oxlint --print-config` the effective set. Folders in `.gitignore` (`dist`, `storybook-static`, the Playwright output) are skipped because Oxlint honours it, so `ignorePatterns` names only committed files that are not ours: the generated API client and schemas, the route tree and `public`. A ban that would need the same message repeated per global, object or override lives in the `jx-code` plugin instead of `no-restricted-*` options.
Style conventions are enforced as errors: function declarations over arrow-function constants, `interface` for object types, type-only imports, named exports (default exports are allowed only for stories, routes, Storybook and tool configuration), braces on every block, kebab-case filenames and no import cycles. `no-restricted-imports` bans `useEffect`, `useLayoutEffect`, `useMemo` and `useCallback` from `react`, named or through a namespace import, because the React Compiler memoizes and effects are replaced by render-time derivation, event handlers, TanStack Query, Hotkeys and Pacer; the vendored primitives under `src/components/ui` are exempt only because they use `import * as React` for types. `typescript/no-non-null-assertion` is a warning in application code until the existing assertions are removed. Vendored primitives under `src/components/ui` are exempt from `no-shadow`, `no-restricted-imports`, `react/no-unstable-nested-components` and `jsx-a11y/label-has-associated-control`.
`unicorn/no-useless-undefined` stays disabled because its autofix removes arguments that Zod `.catch(undefined)` and `useRef(undefined)` require.

Design-system rules come from the `@shadcn/lint` Oxlint JS plugin, registered under `jsPlugins` in the same config; all six of its rules are errors. `no-restyle` allows layout classes (margin, width, alignment, transforms) plus the `stale` utility on every design-system component, and contracts widen that where the page owns part of the styling: containers (`Card`, `Section`, `StaleRegion`, `SplitColumns`, `ScrollRegion`, `RuledLine` and any `*Content`, `*Header`, `*Footer`, `*Group`, `*Panel`) accept spacing; `TableCell` and `TableHead` accept spacing, typography and the muted, income and expense text colours; `*Title` accepts typography; `Skeleton` accepts `rounded-*`; `Input` accepts a font family; `TableRow` accepts the muted text colour for de-emphasised rows. `no-arbitrary-values` allows arbitrary layout values, so grid templates and viewport-relative widths stay inline while type sizes, line heights and letter spacing must come from the theme. `no-unknown-classes` allows sonner's `toaster` marker class. Inside `src/components/ui` the `no-restyle`, `no-arbitrary-values` and `require-static-classes` rules are off, because the primitives style themselves and call their own variant functions; `no-raw-colors` and `no-inline-styles` still apply there. Fix findings with a variant, a contract or a theme token rather than a suppression comment.
A component that must take a caller's styling choice does so through a prop with a fixed set of values (`EmptyText size`, `SelectTrigger size="icon"`, `TextField monospace`), never a class-name prop, so the linter can read what is applied. The one list of classes a component takes is `Table`'s `columns`, typed to width utilities (`w-*`), which are layout and allowed everywhere. Dynamic values reach CSS through custom properties (`style={{ "--meter-fill": … }}` with `w-(--meter-fill)`), typed by the `CSSProperties` augmentation in `frontend/src/react.d.ts`.

The DESIGN.md rules that `@shadcn/lint` cannot express come from a local Oxlint JS plugin, `frontend/lint/design-rules.mjs`, listed as `./lint/design-rules.mjs` under `jsPlugins` with the rule prefix `jx` and switched on for `src/**` in an override, all as errors. Three of its rules read every string and template literal in a file, so `className`, `cn`, `cva` and class constants are all covered; each string is split into utilities and the variant prefixes and `!` are dropped before matching:
- `jx/no-rounded-full`: no `rounded-full` or side `-full` radius. The circles DESIGN.md names are exempt by file in the next override: the splash ring, the `icon-handle` button size, the notification bell count, the dot swatch of `ChartTooltip`, the month page and dashboard month-line skeletons (they stand in for round status icons) and the circle story of `Skeleton`. A new circle is added to that list together with its line in DESIGN.md.
- `jx/no-transition-all`: name the properties that change. Besides Tailwind's own, `global.css` has `transition-width` and `transition-reveal` (opacity, translate and visibility, for an element that fades and slides out of view), and `collapse-rows` animates a collapsible panel through `grid-template-rows`.
- `jx/no-destructive-text`: `text-destructive`, with or without an opacity; error and removal text is `text-expense`. `text-destructive-foreground` on a destructive fill is allowed.

The other three read JSX:
- `jx/no-text-ghost-button`: a `Button` with `variant="ghost"` whose children hold text (JSX text, a string or template literal, or a `t(...)` call). Only icon-only buttons are ghost.
- `jx/no-native-title`: a `title` attribute on an interactive intrinsic element (`a`, `button`, `input`, `select`, `textarea`, `summary`, or any element with `onClick` or an interactive `role`) in `src/features` and `src/components`, with `src/components/ui` exempt; use `Tooltip` or the `Button` `tooltip`. `title` on non-interactive text stays allowed, because DESIGN.md has truncated names, tags and table cells carry their full text there.
- `jx/no-literal-number-placeholder`: a static `placeholder` made only of digits, separators, spaces and minus signs that holds a separator (`0.00`, `1,0000`). Use the money fields' default, which is the locale-formatted zero, or format the value with `useNumberFormat` or `useRateFormat`. `"0"` reads the same in every locale and is allowed.

A second local plugin, `frontend/lint/code-rules.mjs` with the prefix `jx-code`, holds the code-structure rules, switched on for `src/**` in the same override together with one built-in ban:
- `jx-code/no-cross-feature-import`: a feature imports nothing from another feature, apart from the `allow` list in `.oxlintrc.json`; see [Frontend components](architecture/frontend-components.md#frontend-file-layout).
- `jx-code/no-key-listener`: no `addEventListener` for `keydown`, `keyup` or `keypress`; shortcuts go through TanStack Hotkeys.
- `jx-code/layer-imports`: `src/components`, `src/lib`, `src/hooks` and `src/stores` import nothing from `@/features`, and `src/components/ui` also nothing from `@/api`, `@/hooks`, `@/stores` or another `@/components` folder; see [Frontend components](architecture/frontend-components.md).
- `import/no-relative-parent-imports`: no `../` import; another folder is reached by its `@/` path. `src/test/stories/story-session.ts` is exempt because it loads the Storybook preview from `.storybook`, outside `src`.
- `jx-code/no-raw-browser-api`: no `localStorage`, `sessionStorage`, `setTimeout` or `setInterval`, bare or on `window` and `globalThis`; a local binding of the same name is allowed, since the rule reads the global scope as `no-restricted-globals` does. Browser storage goes through `browserStorage()` in `src/lib/browser-storage.ts` and the TanStack DB collections, and waiting through TanStack Pacer. Tests, `src/test`, `browser-storage.ts` itself and the `Sonner` story, whose promise toast needs a slow promise, are exempt.

`frontend/lint/design-rules.test.mjs` and `frontend/lint/code-rules.test.mjs` run each rule through Oxlint's `RuleTester` (`oxlint/plugins-dev`) with good and bad snippets, in the Vitest `unit` project, so `nub run test` and `just check-fast` cover it. The plugin's default export is allowed for `lint/**` like other tool configuration, and the pre-commit hook lints staged `.mjs` files as well.

Frontend formatting rules live in `frontend/.oxfmtrc.json`. Besides layout (100-column width, LF line endings, final newline), the formatter sorts imports into side-effect, Node built-in, external package, `@/` internal and relative groups without blank lines between them, sorts Tailwind classes in `class`, `className`, `cn`, `cva` and `clsx` using `src/global.css` as the Tailwind v4 stylesheet, and sorts `package.json` keys while leaving script order alone. Generated API code, the generated route tree, the MSW worker and build output are ignored. `frontend/.gitattributes` keeps frontend files LF in the repository and the working tree so the formatter and Git agree on Windows.
