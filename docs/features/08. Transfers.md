# Transfers

Back to the [feature walkthrough](<../14. Feature walkthrough with diagrams.md>).

Backend `Transfers`, shown in the Transfers section of `/accounts`. A transfer is never income or expense. Visibility needs either account, mutation needs both.

```mermaid
flowchart TD
    Put["PUT /api/transfers/{id}"] --> Both{"Both current accounts visible?"}
    Both -->|"no"| F403["403 access.forbidden"]
    Both -->|"yes"| Resolve{"Requested accounts visible?"}
    Resolve -->|"no"| F400["400 reference.notFound"]
    Resolve -->|"yes"| Receipt{"TransferImport receipt exists?"}
    Receipt -->|"none"| Amounts
    Receipt -->|"yes"| Locked{"Date changed, or receipt account moved side,<br/>or amount on that side changed?"}
    Locked -->|"yes"| VL["400 value.locked"]
    Locked -->|"no"| Amounts["ITransferAmountResolver, shared with create and import"]
    Amounts --> Cur{"Same currency on both sides?"}
    Cur -->|"yes"| Equal["ReceivedAmount = Amount"]
    Cur -->|"no"| Need["ReceivedAmount required"]
    Equal --> Save["Save"]
    Need --> Save
```

The response carries `fromAccountImported` and `toAccountImported`; the form disables the fixed fields with the hint "Fixed by the import."
