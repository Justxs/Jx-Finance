# User flows

## First installation
Open the app, complete first-run setup, and sign in. The administrator can create other users from Users. Each receives personal starter categories and, once a mail server is configured in Settings, a link that confirms their address. There is still no public registration or email invitation flow.

## Forgotten password
Press "Forgot your password?" on the sign-in screen, which appears only when the installation can send email, and type the address. The screen answers the same sentence whether or not the address belongs to an account here. The emailed link opens a page that sets a new password, works once and expires after an hour; the change signs every browser of that account out. An administrator setting a temporary password from Users remains the way in when there is no mail server, and `--recover-admin` remains the way in when no administrator can sign in at all.

## Enter and correct transactions
Create an account, then add an income or expense. The date defaults to the browser's current local date. Amounts accept a dot or comma decimal separator and are normalized before API submission. Optional split lines must total the transaction amount. Failed creates keep the form open and retain entered values. Saved changes refresh ledger queries. Tags are optional and sit beside the category in the same form: tick as many as the payment deserves, and they apply to the whole transaction, split or not.

## Repeat an entry you type every week
The copy icon on a row opens the add dialog filled from that row, dated today, with its tags and its split lines, and nothing is written until you press Add. For an entry that has no row to copy yet, fill the add dialog and press Save as template, give it a name, and it appears under Templates in the page header ready to start the next one. A template keeps the account, the category, the tags, the description, the amount, whether it is income or expense, and its split lines, but never a date. Templates can be renamed and deleted from the same menu and are remembered by this browser only.

## Name a filter you keep coming back to
Filter the ledger the way you want it, open Saved filters in the page header, type a name and save. The list is in that menu: click a name to bring the filter back, or rename and delete from the same row. What is saved is the filter alone — the search text, the account, the category, the tags, income or expense, and the date range — so applying one never changes how the table is sorted or which page you were on, and the browser's back button undoes it like any other filter change. A saved filter that names a category, account or tag that has since been deleted is marked in the list and still applies exactly as it was saved, which means it answers an empty ledger rather than quietly widening to something you did not ask for. Saved filters are remembered by this browser only.

## Tag what a payment was for
Open Tags from the sidebar and add the labels your household actually uses: a holiday, a renovation, the things somebody will pay back. A tag is personal unless you share it with a household, and a name can only be used once in your own list whatever the casing. Tick tags on a transaction while entering or editing it, or on a selection of rows at once from Transactions. Filter the ledger by tags from the Tags column, from the filter dialog on a phone, or by opening a tag from the report; choosing two tags keeps only the rows that carry both. Reports show expenses by tag under the category breakdowns, with everything untagged as its own row, and a transaction with several tags appears under each of them. Deleting a tag removes it from every transaction and changes nothing else about them.

## Import bank data
Import has no page of its own. Open "Import data" in Settings (administrators) or on Profile (everyone) and press "Import bank statement". The dialog first lists the supported providers, currently only Swedbank; after choosing one, select the target account and upload the CSV in the same dialog. Preview validates column order, a supported currency code, debit/credit direction, dates, amounts and references. Existing references and repeated file rows are flagged. Suspected transfers are initially unselected so they receive explicit review.

Choose income/expense or a transfer with another accessible account. When importing the other bank account's side of the same movement, select the existing transfer rather than creating another. Matching verifies date, amount and direction. The header checkbox selects every row except flagged duplicates, and a category can be set for all selected rows of one type at once. A row whose description exactly matches an earlier transaction of the same type (ignoring case, among the 200 most recent) is pre-filled with that category and marked as suggested until changed. Confirm only selected rows; the dialog then links to the imported rows in Transactions. A retry cannot import the same account/reference again, including after deletion. Changing the target account clears the old preview.

## Budgets and goals
A budget names a category, a limit and a period: weekly, monthly, quarterly or yearly. It always shows the window of that period that holds today, in the installation time zone and, for a weekly budget, from the configured first day of the week; the row says which window it is, and the category name links to exactly those transactions. A category can hold one budget per period, so a weekly and a yearly limit on groceries live side by side, but a second monthly one is refused. Switching on "Carry what is left into the next window" adds the previous window's remainder to the limit, or subtracts an overspend, and the row then shows the base limit, the carried amount and the effective limit the meter fills. A budget created in the current window has nothing to carry yet, and the carry never reaches back more than twelve windows. Edit category, limit, period and rollover in the budget dialog. A goal chooses where its progress comes from. The default is manual: edit the name, target, target date and current amount. The other choice names one visible account and a percentage of it, and progress then follows that account's balance without the current amount being touched, so switching back to manual finds the typed figure again. Neither mode infers savings from transfers, and a goal whose funding account has been archived says its progress is unavailable until it is pointed somewhere else.

## Recurring entries
Choose what the entry records — an expense, an income or a transfer between two of your own accounts — and whether its amount is fixed or variable. An expense or an income takes an optional category of the matching type and an optional default account; a transfer takes the account the money leaves and the account it arrives in instead, and has no category. Each row shows its shape as a tag, and the button on it reads Record payment, Record income or Record transfer.

The pencil opens Edit recurring entry, which changes everything the entry has, the shape included: name, what it records, kind, amount, category, accounts, how often it repeats, the next due date, the reminder lead in days and whether it is active. A shape change that would leave a required field empty is refused under its field, so switching to a transfer asks for the second account before it saves.

The record button opens Confirm recurring entry, which says in words what will be written — an expense, an income, or a move from one named account to another — and asks for the amount of a variable entry, for an account when an expense or income has no default one, and for the amount that arrived when a transfer crosses two currencies. Confirmation uses the displayed expected due date, writes the transaction or the transfer, and advances the entry. A repeated or stale confirmation returns a conflict: the dialog stays open, says the occurrence was already confirmed or the entry changed elsewhere, and the entry is refreshed so the due date shown is the current one before Confirm is pressed again. Dates use calendar arithmetic; a monthly date near month end may clamp to the next month's last valid date. The six-month chart above the list counts fixed expenses only.

## Sharing
Create a household and add an existing user by email. Share an owned account or category. Household members can edit visible records, but only the record owner can change its sharing boundary. Only an account owner can archive it. Removing a member revokes visibility of other users' shared accounts and transaction history, including transactions the removed member entered. The accounts and categories the removed member had shared with the household become personal again, so the remaining members no longer see them and their owner keeps them. Personally owned accounts remain visible to their owner. Editing or deleting a transfer requires access to both of its accounts, and an edit that moves it also requires access to the accounts it moves to.

## Correcting a transfer
The pencil on a row of the Transfers section on Accounts opens Edit transfer, the same form as a new transfer filled with the recorded values: date, amount, received amount, description and both accounts. The amount rules are those of a new transfer. A transfer that came from a bank statement or from Interactive Brokers keeps what the statement said: its date, the imported account and the amount on that account's side cannot change. The description stays editable, and so does the other account, which is how a deposit booked against the wrong funding account is corrected. When both bank entries of a transfer were imported, only the description can change. The form shows this: the fixed fields are disabled with the hint "Fixed by the import." and a sentence at the top names the imported account. An amount in the same currency as an imported receiving side is fixed too, because both sides are one number. Refusals from the server appear inside the dialog, under the field they concern.

## Account recovery
Five wrong passwords or codes in a row lock an account for 15 minutes; sessions that are already open keep working, and the lock ends by itself. Use an unused 2FA recovery code at login if the authenticator is unavailable. A member who forgot their password asks an administrator, who presses the key icon (Reset password) on that user's row of the Users page, types a temporary password and confirms it with their own current password. The user is signed out everywhere, a temporary lockout is lifted, and the user signs in with the temporary password and changes it on Profile. The checkbox "Also reset two-factor authentication" in the same dialog switches off the user's two-factor authentication, for someone who also lost the authenticator and the recovery codes; they enrol again after signing in. A wrong administrator password keeps the dialog open with what was typed and empties only that box. An administrator can reset another administrator this way but not themselves; the profile page changes your own password. Five wrong confirmations lock the administrator like five wrong sign-ins. The temporary password is known to the administrator, so hand it over in person and ask the user to change it at once; the application does not force the change. Deactivate on a user's row asks for confirmation first and says what happens: the user is signed out everywhere, cannot sign in, keeps their data and can be reactivated later. A deactivated user is switched back on by an administrator with Reactivate, the button that takes the place of Deactivate on that row: the old password works again and the sessions from before the deactivation stay closed. Your own row has neither these actions nor Reset password, and the installation refuses to deactivate or demote its last active administrator. If the administrator is locked out completely, run the interactive recovery command from the deployment host; it resets the administrator password and 2FA and revokes sessions. Do not put new passwords in command-line arguments.

## Holding several currencies in one account

An account has one main currency, chosen when it is created. The starting balance is in that currency, and the account total on the Accounts page is every held currency valued in it at the newest exchange rate. When an account holds more than one currency, each balance is listed under the total.

To move money between currencies inside an account, such as selling euros for dollars at a broker, use Convert currency: the exchange icon on the account row, or the button on the Currency conversions section. Enter the amount sold and the amount bought exactly as the statement shows them. The form shows the resulting rate next to the ECB reference rate for that date so a typo is easy to spot. A fee is optional; it may be in either of the two currencies and is saved as an ordinary expense on the same account, so it appears in Transactions, reports and budgets. Deleting the conversion removes its fee transaction too. The pencil on a row of the Currency conversions section opens Edit conversion, the Convert currency form filled with the recorded values; the account cannot change. Editing a conversion changes the date, both amounts and currencies, the description and the fee with its expense category: adding a fee books the expense, changing it updates the same expense including its date and its value in the reporting currency, and clearing it deletes the expense. If the fee expense was split into categories by hand, change it under Transactions instead. Conversions imported from Interactive Brokers have no pencil and say so on their row; correct them at the broker and import again.

A transaction can be in any currency. The currency box beside the amount follows the selected account's main currency until it is changed by hand. In the transactions table a foreign amount shows its value in the reporting currency underneath.

A transfer between accounts in different currencies asks for the received amount as well as the sent amount. When both sides use the same currency the received box is disabled and the amounts are equal.

## Changing installation settings

Administrators open Settings from the Manage group in the sidebar. The page is one form; the bar at the bottom says whether there are unsaved changes and holds Save and Discard changes. Saving applies to every user at once.

Turning a feature off removes it from the navigation and redirects anyone who opens its address to the dashboard. Nothing is deleted: turning it back on brings the data back. Turning off Recurring bills also stops reminders, and turning off Net worth stops the daily snapshot. With Households off, accounts and categories simply show no households to share with. With Multiple currencies off, currency boxes, the Convert action and the Currency conversions section disappear and only the reporting currency can be entered; balances already held in other currencies stay visible.

Currencies you use limits which currencies the pickers offer. A currency that is already on an account or transaction stays selectable on that record.

Changing the reporting currency shows a warning before saving. On save, every transaction is revalued at the exchange rate for its own date. If any rate is missing the save fails and nothing changes; use Sync now and try again. Budgets, goals, assets, debts, bills and net worth history keep their numbers and need reviewing by hand.

Sync now fetches exchange rates immediately, including when automatic sync is off. The language toggle remembers each person's choice in their browser; the default language only applies until they choose.

## Tracking investments

Give the broker account the Investment type and open Investments. Add entry records a buy, sell, dividend, withholding tax, interest, fee or split; the form shows the cash effect before saving, and that cash lands on the account's balance in the security's currency. A buy or sell never counts as income or expense. Dividends and interest count as income, and withholding tax and fee entries as expense, in Reports and on the dashboard, where they appear as "Investment income" and "Investment taxes and fees"; budgets are unaffected, and the gain of a sale is shown only on the Investments page. Selling more than is held is refused. Securities are picked from a shared list; Add security creates one on the spot. Clicking a holding's price sets it by hand, which works for securities you hold on an account you can see. The list is shared by everyone on the installation, so renaming a security or changing its symbol, ISIN, exchange, type or currency is left to an administrator.

The page shows market value, unrealised and realised gain and dividends in the reporting currency, each holding in its own currency with a reporting-currency line beneath when they differ, closed positions folded away, and income by year. The fees column holds standalone fee entries only; the commission of a buy or sell is part of its cost or proceeds and therefore already inside the gain. When a holding has no price or no exchange rate it is left out of the totals and a note says so.

## Importing from Interactive Brokers

In Client Portal open Performance & Reports, Flex Queries, and create an Activity Flex Query with the sections Trades (executions), Cash Transactions, Corporate Actions and Open Positions, XML format, date format yyyyMMdd, and a period such as the last 365 days. Run it, download the XML, and upload it under Import from broker with the account it belongs to. Stock, ETF and fund trades become buys and sells; currency trades become in-account conversions with their commission as an expense; dividends, withholding tax, interest and fees become cash entries; open positions update last prices. In the Corporate Actions section keep at least Type, Action ID, Transaction ID, Report Date, Date/Time, Symbol, Conid, ISIN, Currency, Asset Class, Quantity, Description and Action Description selected, and in Open Positions keep Quantity; selecting every field is the safe choice. Forward and reverse splits become split entries on their report date with the ratio taken from the broker's description ("SPLIT 4 FOR 1" is 4, "SPLIT 1 FOR 10" is 0.1), so the holding and its cost per share follow the split. Mergers, spin-offs, stock dividends, symbol changes and every other corporate action are not booked; the result lists how many of each type were skipped, and they have to be entered by hand. After every import the quantities replayed from the entries are compared with the Open Positions of the report. The result of an upload or a sync counts the splits it booked and, when there is something to check, adds a block headed "Check your holdings": the skipped corporate actions by name with their count, and a table of each security whose quantity differs, with the quantity at the broker and the quantity from your entries, followed by the advice that a split can be entered by hand with Add entry. That is the sign of a corporate action that was not booked, of history from before the first imported period, or of a split entry that was deleted here. Deposits and withdrawals become transfers when a funding account is chosen and are skipped otherwise. Bonds, options, futures and other instruments are skipped and counted. Uploading overlapping periods is safe: every entry is matched by its broker id, including entries deleted here, which stay deleted.

For automatic sync, enable the Flex Web Service in the same place, copy the token, and enter it with the Query ID under Automatic sync. The token is typed once, encrypted, and never shown again. The server then runs the query once a day; Sync now does it immediately and can take up to a minute. The last sync time and any error from Interactive Brokers are shown on the connection.

## Backup and restore

Administrators open Settings and go to Backups. Back up now saves the whole installation (every user, household, account and setting) as one file on the server, with an optional note. Download each backup and keep the copy somewhere else: a backup that lives only beside the database is lost together with it, and nothing is scheduled or copied offsite. The file contains password hashes and two-factor secrets, so treat it as a secret.

Upload adds a backup taken earlier or on another installation to the list without restoring it. Restore asks for the administrator's current password and then replaces everything with the content of the chosen backup; nothing is merged. Everyone is signed out and signs in again with the accounts stored in that backup. A backup written by a different application version is listed but cannot be restored: run the version that wrote it, restore, then upgrade. The stored backups are untouched by a restore, so a wrong restore is undone by restoring another one. Take a fresh backup first when unsure; the application does not do it silently.

## Keyboard shortcuts

Press `?` anywhere outside a text box to see the list. `n` opens the add-transaction dialog, `/` jumps to the search box of the current page, and `g` followed by a letter goes to a page (`d` dashboard, `t` transactions, `a` accounts, `r` reports and so on). Shortcuts are off while a dialog is open and on the sign-in and setup pages.

On Transactions, tick several rows, choose a category under Set category for selected and press Apply to set it on all of them at once. Set tags opens a list beside it and replaces the tags of every ticked row with the ones chosen; split rows can be ticked for that, because a tag belongs to the payment rather than to a split line.
