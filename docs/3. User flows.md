# User flows

## First installation
Open the app, complete first-run setup, and sign in. The administrator can create other users from Users. Each receives personal starter categories. There is no public registration or email invitation flow.

## Enter and correct transactions
Create an account, then add an income or expense. The date defaults to the browser's current local date. Amounts accept a dot or comma decimal separator and are normalized before API submission. Optional split lines must total the transaction amount. Failed creates keep the form open and retain entered values. Saved changes refresh ledger queries.

## Import bank data
On Import CSV (sidebar, or the Import CSV link on Accounts), select the target account and upload a Swedbank CSV. Preview validates column order, a supported currency code, debit/credit direction, dates, amounts and references. Existing references and repeated file rows are flagged. Suspected transfers are initially unselected so they receive explicit review.

Choose income/expense or a transfer with another accessible account. When importing the other bank account's side of the same movement, select the existing transfer rather than creating another. Matching verifies date, amount and direction. The header checkbox selects every row except flagged duplicates, and a category can be set for all selected rows of one type at once. A row whose description exactly matches an earlier transaction of the same type (ignoring case, among the 200 most recent) is pre-filled with that category and marked as suggested until changed. Confirm only selected rows; the page then links to the imported rows in Transactions. A retry cannot import the same account/reference again, including after deletion. Changing the target account clears the old preview.

## Budgets and goals
Budgets track the current configured calendar month. Edit category and limit in the budget dialog. Goals use manual progress: edit the name, target, target date and current amount. They do not infer savings from transfers.

## Bills
Create a fixed bill with an amount or a variable bill without one. Confirm a due occurrence, supplying an account and variable amount where needed. Confirmation uses the displayed expected due date, records the expense and advances the bill. A repeated or stale confirmation returns a conflict and requires refreshed data. Dates use calendar arithmetic; a monthly date near month end may clamp to the next month's last valid date.

## Sharing
Create a household and add an existing user by email. Share an owned account or category. Household members can edit visible records, but only the record owner can change its sharing boundary. Only an account owner can archive it. Removing a member revokes visibility of other users' shared accounts and transaction history, including transactions the removed member entered. Personally owned accounts remain visible to their owner. Modifying/deleting a transfer requires access to both accounts.

## Account recovery
Use an unused 2FA recovery code at login if the authenticator is unavailable. If the administrator is locked out completely, run the interactive recovery command from the deployment host; it resets the administrator password and 2FA and revokes sessions. Do not put new passwords in command-line arguments.

## Holding several currencies in one account

An account has one main currency, chosen when it is created. The starting balance is in that currency, and the account total on the Accounts page is every held currency valued in it at the newest exchange rate. When an account holds more than one currency, each balance is listed under the total.

To move money between currencies inside an account, such as selling euros for dollars at a broker, use Convert currency: the exchange icon on the account row, or the button on the Currency conversions section. Enter the amount sold and the amount bought exactly as the statement shows them. The form shows the resulting rate next to the ECB reference rate for that date so a typo is easy to spot. A fee is optional; it may be in either of the two currencies and is saved as an ordinary expense on the same account, so it appears in Transactions, reports and budgets. Deleting the conversion removes its fee transaction too.

A transaction can be in any currency. The currency box beside the amount follows the selected account's main currency until it is changed by hand. In the transactions table a foreign amount shows its value in the reporting currency underneath.

A transfer between accounts in different currencies asks for the received amount as well as the sent amount. When both sides use the same currency the received box is disabled and the amounts are equal.

## Changing installation settings

Administrators open Settings from the Manage group in the sidebar. The page is one form; the bar at the bottom says whether there are unsaved changes and holds Save and Discard changes. Saving applies to every user at once.

Turning a feature off removes it from the navigation and redirects anyone who opens its address to the dashboard. Nothing is deleted: turning it back on brings the data back. Turning off Recurring bills also stops reminders, and turning off Net worth stops the daily snapshot. With Households off, accounts and categories simply show no households to share with. With Multiple currencies off, currency boxes, the Convert action and the Currency conversions section disappear and only the reporting currency can be entered; balances already held in other currencies stay visible.

Currencies you use limits which currencies the pickers offer. A currency that is already on an account or transaction stays selectable on that record.

Changing the reporting currency shows a warning before saving. On save, every transaction is revalued at the exchange rate for its own date. If any rate is missing the save fails and nothing changes; use Sync now and try again. Budgets, goals, assets, debts, bills and net worth history keep their numbers and need reviewing by hand.

Sync now fetches exchange rates immediately, including when automatic sync is off. The language toggle remembers each person's choice in their browser; the default language only applies until they choose.

## Tracking investments

Give the broker account the Investment type and open Investments. Add entry records a buy, sell, dividend, withholding tax, interest, fee or split; the form shows the cash effect before saving, and that cash lands on the account's balance in the security's currency. A buy or sell never counts as income or expense, so reports and budgets are unaffected. Selling more than is held is refused. Securities are picked from a shared list; Add security creates one on the spot. Clicking a holding's price sets it by hand.

The page shows market value, unrealised and realised gain and dividends in the reporting currency, each holding in its own currency with a reporting-currency line beneath when they differ, closed positions folded away, and income by year. When a holding has no price or no exchange rate it is left out of the totals and a note says so.

## Importing from Interactive Brokers

In Client Portal open Performance & Reports, Flex Queries, and create an Activity Flex Query with the sections Trades (executions), Cash Transactions and Open Positions, XML format, date format yyyyMMdd, and a period such as the last 365 days. Run it, download the XML, and upload it under Import from broker with the account it belongs to. Stock, ETF and fund trades become buys and sells; currency trades become in-account conversions with their commission as an expense; dividends, withholding tax, interest and fees become cash entries; open positions update last prices. Deposits and withdrawals become transfers when a funding account is chosen and are skipped otherwise. Bonds, options, futures and other instruments are skipped and counted. Uploading overlapping periods is safe: every entry is matched by its broker id, including entries deleted here, which stay deleted.

For automatic sync, enable the Flex Web Service in the same place, copy the token, and enter it with the Query ID under Automatic sync. The token is typed once, encrypted, and never shown again. The server then runs the query once a day; Sync now does it immediately and can take up to a minute. The last sync time and any error from Interactive Brokers are shown on the connection.
