# 11. Milestones & tasks

A build order front-loaded on **developer experience** and on **getting something you actually use early**. Scaffolding, codegen, and feedback loops come first; then the **core ledger** (so the app is useful and validated by real use); then the **auth spine** before the app is ever exposed; then the rest. Milestones are roughly sequential; tick tasks as you go.

> [!tip] Each milestone ends with a **Definition of done** — don't move on until it's true. Decisions referenced as `D…` live in [[9. Open questions & decisions]].

> [!info] **2026-05-30 reset.** Build order changed: **ledger before auth** ([[9. Open questions & decisions|D51]]), **households & sharing deferred** to M6 ([[9. Open questions & decisions|D50]]), **2FA optional** ([[9. Open questions & decisions|D52]]), and **email decoupled from onboarding** ([[9. Open questions & decisions|D53]]). M0 is trimmed to "just enough to ship feature 1," with heavier tooling added as it earns its place.

- **[[#M0 — Foundations (slim)|M0]]** — just enough scaffolding + the codegen loop ← *start here*
- **[[#M1 — Core ledger|M1]]** — accounts, categories, transactions, dashboard, on localhost (the MVP value)
- **[[#M2 — Auth & hardening|M2]]** — the security spine, before any remote exposure

## M0 — Foundations (slim)
Just enough to **ship feature 1** — not the whole toolbox. Goal: **`just dev` boots the stack, a ping endpoint round-trips through a *generated* client, and CI is green.** Add the rest (see the note at the end) when it first earns its place.

### Repo & tooling
- [ ] Create the repo with `frontend/` and `backend/` ([[7. Architecture notes#Project layout (repo root)]])
- [ ] `.gitignore`, `.editorconfig`, and a `README` with the run steps
- [ ] **Task runner** (`justfile` or `Taskfile.yml`): `dev`, `gen`, `test`, `up`, `lint` ([[9. Open questions & decisions|D33]])
- [ ] `.env.example` with `POSTGRES_*`, connection string, `App__TimeZone` ([[9. Open questions & decisions|D56]]), app secrets *(SMTP keys can wait — email is deferred, [[9. Open questions & decisions|D53]])*

### Containers & database
- [ ] `docker-compose.yml`: PostgreSQL service with a named volume
- [ ] Add API + frontend services; `just up` brings the stack up ([[9. Open questions & decisions|D5]])
- [ ] Confirm Postgres persists across `down`/`up`

### Backend skeleton
- [ ] Solution + 3 projects: `Api` (vertical slices + host), `Domain`, `Infrastructure` (+ `Tests`) ([[7. Architecture notes#Backend structure]])
- [ ] **FastEndpoints** wired in `Program.cs`; a `GET /api/ping` endpoint ([[9. Open questions & decisions|D16]])
- [ ] **Serilog** structured logging ([[9. Open questions & decisions|D18]])
- [ ] **Global ProblemDetails** error handling + the **`Result<T>`** type ([[9. Open questions & decisions|D23]])
- [ ] **Health checks** (DB ping) wired to the Docker healthcheck ([[9. Open questions & decisions|D27]])
- [ ] **Application-service pattern**: feature service interface + impl, injected into endpoints ([[7. Architecture notes#Application services, briefly]])

### Data layer foundations
- [ ] EF Core `DbContext` in `Infrastructure`
- [ ] **Base entity**: `CreatedAt`, `UpdatedAt`, `IsDeleted` + a global query filter for soft-delete ([[9. Open questions & decisions|D24]])
- [ ] **Ownership field**: `UserId` on the base ownable entity — **no `Scope`/`HouseholdId`** (sharing deferred, [[9. Open questions & decisions|D50]])
- [ ] First migration; **migrations apply on startup, after a `pg_dump`** ([[9. Open questions & decisions|D39]], [[9. Open questions & decisions|D54]])
- [ ] UTC timestamps + the configured period timezone enforced ([[9. Open questions & decisions|D42]], [[9. Open questions & decisions|D56]])

### API contract & docs (the payoff loop)
- [ ] **NSwag** OpenAPI document generating from FastEndpoints ([[9. Open questions & decisions|D17]])
- [ ] **Scalar** docs UI serving from the spec
- [ ] Export `openapi.json` via a `just gen`-friendly command
- [ ] **Orval** config: `openapi.json` → typed TanStack Query hooks in `src/api/generated/`
- [ ] `src/api/client.ts` (base URL, cookies, error mapping)
- [ ] Call `GET /api/ping` from a component **via the generated hook** — proves the whole loop end to end

### Frontend skeleton
- [ ] Vite + React + TypeScript app
- [ ] **TanStack Router** (file-based), **Query**, **Store** ([[9. Open questions & decisions|D20]])
- [ ] **Tailwind** + **shadcn/ui** init ([[9. Open questions & decisions|D28]])
- [ ] **react-i18next** with `en` + a language switch; structure in now, **`lt` translations can lag** ([[9. Open questions & decisions|D21]])
- [ ] Base layout, a query client, and a global error→toast handler ([[9. Open questions & decisions|D30]]); `refetchOnWindowFocus` on ([[9. Open questions & decisions|D38]])
- [ ] Shared `useMoney()` / `useDate()` `Intl` formatters ([[8. Non-functional requirements#Localization (i18n)]])

### Quality gates (start light)
- [ ] Backend tests: **xUnit + Testcontainers** (real Postgres) — at least one round-trip test ([[9. Open questions & decisions|D26]])
- [ ] Frontend tests: **Vitest + RTL + MSW** — at least the ping component
- [ ] Lint/format: **Oxc** (frontend) + .NET analyzers
- [ ] **CI** (GitHub Actions or Azure DevOps — [[9. Open questions & decisions|open]]): build / test / lint + **client-drift check** ([[9. Open questions & decisions|D33]])

> [!note] **Add when it earns its place — don't block feature 1 on these.** **Strongly-typed IDs** + the **`Money` value object** ([[9. Open questions & decisions|D22]], [[9. Open questions & decisions|D40]]) are high-payoff but optional to start — a plain `decimal` on a `NUMERIC(_,2)` column is already correct; add the wrappers once the ledger exists. **NetArchTest** layering tests: add the first time you catch a layering slip ([[9. Open questions & decisions|D26]]). **Service decorators / FE processors** for cross-cutting: add when you have a real cross-cutting concern, not before. The full **`lt`** translation pass can follow EN.

> [!success] **Definition of done:** `just dev` runs DB + API + frontend; the ping page renders data fetched through a generated hook; `just gen` regenerates the client; `just test` passes; CI is green and fails on client drift.

## M1 — Core ledger
The MVP people actually use — built on localhost with a **single seeded user, no login yet** ([[9. Open questions & decisions|D51]]). ([[2. Features#Must-have (MVP)]])

- [ ] Seed a single dev user; **stamp `UserId` on every row** and apply the central `UserId` filter on every query (the isolation seam, ready for M2) ([[9. Open questions & decisions|D50]])
- [ ] **Accounts** CRUD + computed `CurrentBalance` ([[5. Data model#Account]])
- [ ] **Categories** CRUD; seed starter categories (EN; `lt` later); delete → uncategorize ([[9. Open questions & decisions|D8]])
- [ ] **Transactions** CRUD (income/expense) ([[5. Data model#Transaction]])
- [ ] **Dashboard**: total balance + this month's income vs. expense (period in `App__TimeZone`, [[9. Open questions & decisions|D56]]) ([[6. API surface#Dashboard (MVP)]])
- [ ] Frontend: dashboard, **fast** add-transaction (optimistic list update), accounts, categories, transactions list (TanStack Table)
- [ ] Money/dates via the shared formatters

> [!success] **Done:** add/edit/delete transactions across multiple accounts; the dashboard and balances reflect them immediately. **Then use it with your own real data for a couple of weeks before moving on** — let real use shape M2+.

## M2 — Auth & hardening
The security spine — finish this **before the app is reachable** over WireGuard ([[9. Open questions & decisions|D51]]). It slots onto the `UserId` seam already in place. ([[3. User flows#Flow: Sign in]], [[6. API surface#Auth (MVP)]])

- [ ] ASP.NET Core **Identity** + cookie auth, **1-day** session ([[9. Open questions & decisions|D36]])
- [ ] `User` entity: `Role` (Admin/Member), `EmailConfirmed`, `TwoFactorEnabled` ([[5. Data model#User]])
- [ ] **First-run setup page** + `POST /api/setup` — admin sets a password **directly**, no email step ([[9. Open questions & decisions|D44]], [[9. Open questions & decisions|D53]])
- [ ] Login / logout / `me`; **"remember me"** longer cookie; swap the seeded user for the real session
- [ ] **Optional 2FA (TOTP)** enrolment + recovery codes — offered, not required ([[9. Open questions & decisions|D52]])
- [ ] **Admin user management**: create a user with a password set directly, list, change role, deactivate ([[6. API surface#Users (MVP)]])
- [ ] **Rate limiting** on `/auth/*` ([[9. Open questions & decisions|D27]])
- [ ] Frontend: auth pages, route guards, optional-2FA + setup screens

> [!success] **Done:** a fresh install walks first-run setup → admin signs in (2FA only if they enabled it) → can create another user who signs in and sees only their own data. Safe to expose over WireGuard.

> [!note] **Email features are deferred ([[9. Open questions & decisions|D53]]).** Email verification, password-reset-by-email, and notification email land later (set up in M5, or pulled earlier if you want them). The `IEmailSender` seam goes in here so they slot in cleanly.

## M6 — Households & sharing
Later — **deferred from v1.1** ([[9. Open questions & decisions|D50]]). Build this only when sharing with family is a real, present need. It adds onto the `UserId` already on every row as an *additive* migration. ([[5. Data model#Ownership]])

- [ ] **Resolve the parked questions first** ([[9. Open questions & decisions#Households & sharing (deferred — D50)|Households & sharing (deferred — D50)]]): account re-scoping, shared categories, member-leaves, default scope
- [ ] Add `Household` + `HouseholdMembership` tables; add `Scope` (`Personal`/`Shared`) + `HouseholdId` columns to ownable entities (migration)
- [ ] **Account is the scope anchor** — transactions/transfers/lines inherit its scope (pick join vs. denormalised copy)
- [ ] Expand the central filter to `UserId = me OR (Scope = Shared AND HouseholdId ∈ my memberships)`; **integration-test cross-scope leakage hard** ([[9. Open questions & decisions#Risks & mitigations]])
- [ ] **Households** + **member management** endpoints (household **Owner** role) ([[6. API surface#Households]])
- [ ] Frontend: **active-scope selector** (Personal / household) in the header — TanStack Store + typed search param ([[7. Architecture notes#Frontend conventions]])

> [!success] **Done:** create a household, invite an existing user, mark an account Shared; both members see and edit it; switching active scope re-scopes the dashboard; personal accounts stay private.
